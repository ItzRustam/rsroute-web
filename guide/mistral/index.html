MistralAI

The Mistral routes use the plain parameter set — no reasoning extras, no provider preferences. top_p is supported here, unlike Groq and OpenRouter.

Overview

What it is

Mistral's models, reached through LangChain's Mistral adapter. The route is the simplest of the four: it forwards the standard parameter set and nothing else.

Default model: mistral-small-2603. Requires MISTRAL_API_KEY in the gateway's .env.

Endpoints

Routes

Mistral routes
Method Path Purpose
POST /v1/mistral/chat Plain text-to-text chat.
POST /v1/mistral/agent Tool-binding agent. Requires tools_info.
GET /v1/mistral/parameter Parameter info. /parameters is an alias.
Request body

Server parameters

The Mistral parameter endpoint returns the base set unchanged — no fields are removed and none are added.

Mistral request parameters
Parameter Type Default Details
query opt any "Hello" String is wrapped into a user message; a list is passed through.
master_key opt string "" Checked only when ENABLE_AUTH=true.
model opt string "mistral-small-2603" Any Mistral model id.
temperature opt float 0.7 Sampling creativity.
max_tokens opt integer 2048 Upper bound on generated tokens.
top_p opt float 1.0 Nucleus sampling boundary. Supported on Mistral.
end_point opt string | null null Custom base URL for the Mistral client.
tools_info agent only array<object> null List of {"name", "description"} pairs.
No reasoning parameters

thinking_level and thinking_budget are not part of the Mistral route signature. Sending them has no effect.

Plain HTTP

REST example

import requests

resp = requests.post(
    "http://localhost:8000/v1/mistral/chat",
    json={
        "query": "What is the weather in Paris?",
        "master_key": "RSRoute_my_key",
        "model": "mistral-small-2603",
        "temperature": 0.7,
        "max_tokens": 2048,
        "top_p": 1.0,
    },
    timeout=60,
)

data = resp.json()
if data["error"] != "No Error Found":
    raise RuntimeError(data["error"])

print(data["content"])
const resp = await fetch("http://localhost:8000/v1/mistral/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    query: "What is the weather in Paris?",
    master_key: "RSRoute_my_key",
    model: "mistral-small-2603",
    temperature: 0.7,
    max_tokens: 2048,
    top_p: 1.0,
  }),
});

const data = await resp.json();
if (data.error !== "No Error Found") {
  throw new Error(data.error);
}

console.log(data.content);

Agent call

resp = requests.post(
    "http://localhost:8000/v1/mistral/agent",
    json={
        "query": "What is the weather in Paris?",
        "master_key": "RSRoute_my_key",
        "tools_info": [
            {"name": "web_search",
             "description": "Search the web"},
        ],
    },
    timeout=120,
)

print(resp.json()["tool_calls"])
rsroute client

rsroute client

from rsroute.chat_models import ChatMistral

mistral = ChatMistral(
    model="mistral-small-2603",
    temperature=0.7,
    max_tokens=2048,
)

result = mistral.invoke(query="What is the weather in Paris?")
print(result["content"])

ChatMistralAI and MistralAI are aliases for the same class.

Agent

from rsroute.agents import MistralAgent

agent = MistralAgent(
    tools=[web_search],
    model="mistral-small-2603",
)

result = agent.invoke(query="What is the weather in Paris?")
print(result["content"])
print(result["tools_used"])

Gotchas

Notes

  • /v1/mistral/parameter and /v1/mistral/parameters both work.
  • Missing MISTRAL_API_KEY returns error: "No MistralAI API Key Found, try to edit `.env`" with HTTP 200.
  • Unlike Gemini, the Mistral route does not wrap model construction in a try block — a bad model id surfaces as a Request Error instead of Invalid Request.
  • Embedding endpoints are not implemented.
