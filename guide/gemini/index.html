Provider guide

Google Gemini

The Gemini routes are the only ones that expose reasoning controls. thinking_level and thinking_budget let you tune how much chain-of-thought Gemini 3+ models produce before answering.

Overview

What it is

Google's Gemini models, reached through LangChain's Gemini adapter. RSRoute wraps it with the standard envelope and adds pass-through for Gemini's reasoning parameters.

Default model: gemini-3.5-flash-lite. Requires GOOGLE_API_KEY in the gateway's .env.

Only provider with reasoning controls

thinking_level and thinking_budget are accepted on Gemini routes only. Mistral, Groq and OpenRouter ignore them.

Endpoints

Routes

Gemini routes
Method Path Purpose
POST /v1/gemini/chat Plain text-to-text chat.
POST /v1/gemini/agent Tool-binding agent. Requires tools_info.
GET /v1/gemini/parameter Parameter info. /parameters is an alias.
Request body

Server parameters

These are the fields the Gemini routes read from the JSON body. Both /chat and /agent accept the same set, plus tools_info on the agent route.

Gemini request parameters
Parameter Type Default Details
query opt any "Hello" String is wrapped into a user message; a list is passed through.
master_key opt string "" Checked only when ENABLE_AUTH=true.
model opt string "gemini-3.5-flash-lite" Any Gemini model id.
temperature opt float 0.7 Sampling creativity.
max_tokens opt integer 2048 Upper bound on generated tokens.
top_p opt float 1.0 Nucleus sampling boundary. Supported on Gemini.
end_point opt string | null null Custom base URL for the Gemini client.
thinking_level opt string | null null Controls reasoning depth on Gemini 3+ models.
thinking_budget opt integer | null null Token budget for reasoning / chain-of-thought.
tools_info agent only array<object> null List of {"name", "description"} pairs.
Plain HTTP

REST example

A chat call with reasoning enabled. The response is the standard envelope. 

import requests

resp = requests.post(
    "http://localhost:8000/v1/gemini/chat",
    json={
        "query": "Explain vector databases",
        "master_key": "RSRoute_my_key",
        "model": "gemini-3.5-flash-lite",
        "temperature": 0.7,
        "max_tokens": 2048,
        "top_p": 1.0,
        "thinking_level": "high",
        "thinking_budget": 1024,
    },
    timeout=60,
)

data = resp.json()
if data["error"] != "No Error Found":
    raise RuntimeError(data["error"])

print(data["content"])
const resp = await fetch("http://localhost:8000/v1/gemini/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    query: "Explain vector databases",
    master_key: "RSRoute_my_key",
    model: "gemini-3.5-flash-lite",
    temperature: 0.7,
    max_tokens: 2048,
    top_p: 1.0,
    thinking_level: "high",
    thinking_budget: 1024,
  }),
});

const data = await resp.json();
if (data.error !== "No Error Found") {
  throw new Error(data.error);
}

console.log(data.content);

Agent call

Same body plus tools_info. The response adds tool_calls. 

resp = requests.post(
    "http://localhost:8000/v1/gemini/agent",
    json={
        "query": "What is the weather in Paris?",
        "master_key": "RSRoute_my_key",
        "tools_info": [
            {"name": "web_search",
             "description": "Search the web"},
        ],
    },
    timeout=120,
)

print(resp.json()["tool_calls"])
rsroute client

rsroute client

from rsroute.chat_models import ChatGemini

gemini = ChatGemini(
    model="gemini-3.5-flash-lite",
    temperature=0.7,
    max_tokens=2048,
    thinking_level="high",
    thinking_budget=1024,
)

result = gemini.invoke(query="Explain vector databases")
print(result["content"])

Agent

from rsroute.agents import GeminiAgent

agent = GeminiAgent(
    tools=[web_search],
    model="gemini-3.5-flash-lite",
    max_tool_calls=12,
    thinking_level="high",
)

result = agent.invoke(query="What is the weather in Paris?")
print(result["content"])
print(result["tools_used"])

Gotchas

Notes

  • /v1/gemini/parameter and /v1/gemini/parameters both work — the route is registered twice.
  • Missing GOOGLE_API_KEY returns error: "No Google API Key Found, try to edit `.env`" with HTTP 200.
  • thinking_level and thinking_budget are passed straight through — RSRoute does not validate their values.
  • Embedding endpoints are not implemented; the root index reports "Coming Soon".
