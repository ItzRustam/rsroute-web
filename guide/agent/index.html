Agents

Agents let the model decide when to call a tool. RSRoute advertises your tools to the model and returns its intent — the client then runs the tool locally and feeds the result back, looping until the model stops asking.

Basics

Overview

An agent is a chat model with tools bound to it. The difference is who executes them:

  • The server never runs your tools. It binds stub tools by name and description, and returns the model's tool_calls intent.
  • The client runs the real tool, appends the result as a tool message, and calls the server again.

That keeps the gateway stateless and means arbitrary code never executes on the server. 

from rsroute.agents import GeminiAgent

agent = GeminiAgent(tools=[web_search])
result = agent.invoke(query="Latest news on GPT-6 Astra")

print(result["content"])
print(result["tools_used"])
Mechanics

How the loop works

invoke() on an agent is a ReAct-style loop. Each iteration is one HTTP round trip.

  1. The client sends your query plus tools_info to /v1/<provider>/agent.
  2. If the response has no tool_calls, the loop ends and the response is returned as-is.
  3. Otherwise the client takes the first tool call, looks up the tool by name, and invokes it with the model's arguments.
  4. The tool result is appended as a tool message with the matching tool_call_id, and the whole message history is sent back.
  5. Steps 2–4 repeat until the model stops calling tools or max_tool_calls is reached.
One tool per round trip

The loop handles the first tool call in each response. If the model asks for several tools at once, the remaining ones are not executed in that iteration.

Token usage is accumulated across every step and written back into usage_metadata on the final result, so the numbers reflect the whole loop rather than the last call.

Input

Defining tools

The client accepts a list of LangChain StructuredTool objects. Anything else raises TypeError, and an empty or missing list raises ValueError. 

from langchain_core.tools import tool

@tool
def web_search(query: str) -> str:
    """Search the web and return the top results."""
    return "..."

@tool
def calculator(expression: str) -> str:
    """Evaluate a mathematical expression."""
    return str(eval(expression))

agent = GeminiAgent(tools=[web_search, calculator])

Only name and description are sent to the server. The model never sees your implementation — it sees the signature and the docstring, which is why the description matters.

What the client sends

Each tool is reduced to a two-key dictionary before the request: 

[
  {"name": "web_search", "description": "Search the web and return the top results."},
  {"name": "calculator", "description": "Evaluate a mathematical expression."}
]

The server validates this shape strictly: it must be a non-empty list of dicts, each with both name and description as strings.

Constructor

Arguments

Agent classes accept the chat model arguments plus the two below. The defaults differ in two places: timeout is longer, and tools is required.

Agent constructor arguments
Argument Type Default Details
tools required list[StructuredTool] — Must be non-empty. Every item must be a LangChain StructuredTool.
max_tool_calls opt int 10 Hard cap on loop iterations. Exceeding it raises BufferError.
timeout opt int 120 Per-request HTTP timeout in seconds. Higher than chat models because of the loop.
model opt str | None None Same as chat models — server default applies when omitted.
master_key opt str | None None Resolved from .env / environment when omitted.
rsroute_url opt str | None http://0.0.0.0:8000 The resolved URL must end in /agent, or the constructor raises RuntimeError.
system_prompt opt str | SystemMessage | any None Prepended to the message history on the first call.
temperature opt float | None None Omitted from the request when None.
max_tokens opt int | None None Omitted from the request when None.
end_point opt str | None None Provider base URL override, forwarded to the server.
**kwargs opt any — Forwarded verbatim in the request body when not None.
Differences

Per provider

All four agent classes behave identically. Only the endpoint and the default model change — plus Gemini's reasoning extras.

GeminiAgent

Endpoint /v1/gemini/agent. Adds thinking_level and thinking_budget. 

from rsroute.agents import GeminiAgent

agent = GeminiAgent(
    tools=[web_search],
    model="gemini-3.5-flash-lite",
    max_tool_calls=12,
    thinking_level="high",
)

MistralAgent

Endpoint /v1/mistral/agent. Default model mistral-small-2603.

from rsroute.agents import MistralAgent

agent = MistralAgent(
    tools=[web_search],
    model="mistral-small-2603",
)

GroqAgent

Endpoint /v1/groq/agent. Default model openai/gpt-oss-120b.

from rsroute.agents import GroqAgent

agent = GroqAgent(
    tools=[web_search],
    model="openai/gpt-oss-120b",
)

OpenRouterAgent

Endpoint /v1/openrouter/agent. Default model deepseek/deepseek-v4.1-flash. Also accepts app_title, app_url, app_categories, max_retries and providers. Alias ChatOpenRouterAgent. 

from rsroute.agents import OpenRouterAgent

agent = OpenRouterAgent(
    tools=[web_search],
    model="deepseek/deepseek-v4.1-flash",
    providers={"order": ["DeepSeek"]},
)

Full field reference: OpenRouter guide.

Output

Return value

The agent returns the same envelope as a chat model, plus two additions:

  • tool_calls — the model's final intent list. Empty when the loop finished cleanly.
  • tools_used — the names of every tool the client actually executed, in order. 
result = agent.invoke(query="What is the weather in Paris?")

print(result["content"])       # final answer
print(result["tools_used"])    # ["web_search"]
print(result["usage_metadata"]) # summed across all steps
Content may be reshaped

If the final content is a single-element list whose item is a dict with a text key, the client unwraps it to a plain string and moves extras to the top level. Otherwise the raw content is returned untouched.

Under the hood

REST equivalent

Without the client you drive the loop yourself. The first request is a normal POST with tools_info. 

import requests

resp = requests.post(
    "http://localhost:8000/v1/gemini/agent",
    json={
        "query": "What is the weather in Paris?",
        "master_key": "RSRoute_my_key",
        "tools_info": [
            {"name": "web_search",
             "description": "Search the web"},
        ],
    },
    timeout=120,
)

data = resp.json()

# The model asked for a tool — run it yourself, then send the result back.
for call in data["tool_calls"]:
    print(call["name"], call["args"], call["id"])
const resp = await fetch("http://localhost:8000/v1/gemini/agent", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    query: "What is the weather in Paris?",
    master_key: "RSRoute_my_key",
    tools_info: [
      { name: "web_search", description: "Search the web" },
    ],
  }),
});

const data = await resp.json();

// The model asked for a tool — run it yourself, then send the result back.
for (const call of data.tool_calls) {
  console.log(call.name, call.args, call.id);
}

Sending the tool result back

Append the assistant turn and a tool message, then post the whole history as query. 

messages = [
    {"role": "user", "content": "What is the weather in Paris?"},
    {"role": "assistant",
     "content": "",
     "tool_calls": data["tool_calls"]},
    {"role": "tool",
     "content": "18°C, light rain",
     "tool_call_id": data["tool_calls"][0]["id"]},
]

resp = requests.post(
    "http://localhost:8000/v1/gemini/agent",
    json={"query": messages, "master_key": "RSRoute_my_key",
          "tools_info": [{"name": "web_search", "description": "Search the web"}]},
    timeout=120,
)

This is exactly what rsroute automates — use the client unless you need the loop in another language.

Guardrails

Limits & errors

The agent raises on the client side in a few specific cases:

  • ValueError — tools is None or empty.
  • TypeError — a tool is not a LangChain StructuredTool.
  • RuntimeError — the resolved URL does not end in /agent.
  • BufferError — the loop hit max_tool_calls.
  • ValueError — the model named a tool that is not in your list, or supplied no arguments for a call.
BufferError is not a provider error

Hitting max_tool_calls raises out of invoke() — it does not come back in the response envelope. Catch it if your tools can loop. 

try:
    result = agent.invoke(query="Research this thoroughly")
except BufferError:
    print("Agent exceeded max_tool_calls")
ainvoke is not async

ainvoke() exists on every agent class but currently forwards to the synchronous invoke(). It returns a plain dict, not an awaitable — do not await it.
