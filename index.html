The problem

Every project shouldn't rebuild the same LLM plumbing.

Without a gateway, each app embeds its own provider client, its own key management and its own error handling. RSRoute collapses that duplication into a single service you run yourself.

Why RSRoute

Built for teams that ship against more than one model.

A stable REST contract over LangChain's provider adapters — so provider churn never reaches your application code.

One API, many providers

The same request shape works for Gemini, Mistral, Groq and OpenRouter. Switching provider is a URL change, not a refactor — and OpenRouter alone opens up hundreds of models behind that one route.

Centralised secrets

Provider keys live in one .env on one host. Applications never see them — they only hold the gateway master key.

Consistent envelope

content, usage_metadata, response_metadata and initlized_parameters — always present, always the same keys.

Agentic tool-calling

Send tools_info and the model decides which tool to call. RSRoute advertises tools but never executes them — your app stays in control.

Stateless by design

No database, no session store, no queue. Scale horizontally by running more replicas behind a load balancer.

Self-hosted & containerised

Two Dockerfiles, CI on every push, and no SaaS dependency. Your prompts and keys never leave your infrastructure.

API surface

Every route, documented by the gateway itself.

GET / returns a machine-readable index of all routes. Each provider also exposes a parameter endpoint describing every accepted field.

MistralAI POST /v1/mistral/chat POST /v1/mistral/agent GET /v1/mistral/parameter mistral-small-2603

OpenRouter new POST /v1/openrouter/chat POST /v1/openrouter/agent GET /v1/openrouter/parameters deepseek/deepseek-v4.1-flash

OpenRouter also accepts /v1/openrouter/parameter as an alias for the parameters endpoint, matching the Gemini and Mistral routes.

01

Chat — plain text-to-text

Wraps the LangChain chat model and calls .invoke(). Send a query, get content back.

02

Agent — tool intent, not execution

Bind stub tools by name and description. The model returns tool_calls; your app runs them.

03

Parameters — self-documenting

Every accepted field, its type and its default, straight from the running gateway.

{
  "content": "Here is the summary…",
  "query": ["Summarise this document"],
  "error": "No Error Found",
  "login": true,
  "auth": true,
  "usage_metadata": { /* tokens in / out */ },
  "response_metadata": { /* provider raw */ },
  "initlized_parameters": {
    "model": "gemini-3.5-flash-lite",
    "temperature": 0.7
  },
  "tool_calls": []
}

Errors are reported in-band

Auth failures, missing provider keys and provider exceptions all return HTTP 200 with error populated and login: false. Clients must inspect the body, not the status code.

New provider

OpenRouter is now a first-class route.

One key, hundreds of models. OpenRouter aggregates frontier and open-weight models behind a single API — and RSRoute now exposes it with the exact same envelope, auth and agent contract as every other provider.

01

Hundreds of models, one route

Point model at any OpenRouter model id — deepseek/deepseek-v4.1-flash is the default, but openai/gpt-4o-mini, anthropic/claude-* and open-weight models work the same way.

02

Provider routing preferences

Pass providers to steer OpenRouter's own routing — for example {"order": ["OpenAI"]} to prefer a specific upstream, or to avoid ones you don't want.

03

App attribution built in

app_title, app_url and app_categories are forwarded to OpenRouter so your usage shows up correctly in its rankings and dashboard.

04

Retries and custom base URL

max_retries defaults to 2 for transient upstream failures, and end_point lets you override the base URL when you need a proxy. 

from rsroute.chat_models import ChatOpenRouter

openrouter = ChatOpenRouter(
    model="deepseek/deepseek-v4.1-flash",  # default
    temperature=0.7,
    max_tokens=4096,
    app_title="My App",
    app_url="https://example.com",
    providers={"order": ["DeepSeek"]},
)

print(openrouter.invoke(query="Hello OpenRouter!"))
import requests

resp = requests.post(
    "http://localhost:8000/v1/openrouter/chat",
    json={
        "query": "Explain mixture-of-experts",
        "master_key": "RSRoute_my_key",
        "model": "deepseek/deepseek-v4.1-flash",
        "temperature": 0.7,
        "max_tokens": 4096,
        "app_title": "My App",
        "app_url": "https://example.com",
        "max_retries": 2,
        "providers": {"order": ["DeepSeek"]},
    },
    timeout=60,
)

print(resp.json()["content"])
from rsroute.agents import OpenRouterAgent

openrouter_agent = OpenRouterAgent(
    tools=[web_search],
    model="deepseek/deepseek-v4.1-flash",
    max_tool_calls=10,  # default
)

print(openrouter_agent.invoke(
    query="Search the latest news on open-weight models"
))

One extra environment variable

Add OPENROUTER_API_KEY to your .env alongside the other provider keys. If it's missing, the OpenRouter routes return error: "No OpenRouter API Key Found, try to edit `.env`" instead of failing silently.

Every accepted field, its type and its default is documented in the chat model guide and the agent guide.

Quickstart

Running in four steps.

Install the rsroute Python client, point it at your gateway, and call any provider with the same code.

Install the client

The rsroute package is a thin Python wrapper around the gateway. Requires Python 3.14+. 

pip install rsroute

Run the gateway

The client needs an RSRoute server to talk to. Clone it, add your provider keys to .env, and boot it. 

git clone https://github.com/ItzRustam/rsroute.git
cd rsroute
pip install -r requirements.txt
python run_server.py

Set your master key

The client reads the key from .env automatically. Any of these names work: rsroute_token, master_key, rsroute_key, rsroute_master_key. 

# .env
rsroute_token=RSRoute_my_key

Call any provider

Same shape for every provider — swap the class, keep the code. rsroute_url defaults to http://0.0.0.0:8000. 

from rsroute.chat_models import (
    ChatGemini, ChatMistral, ChatGroq, ChatOpenRouter,
)

# Gemini
gemini = ChatGemini(
    model="gemini-3.5-flash-lite",
    rsroute_url="http://0.0.0.0:8000",  # default
)
print(gemini.invoke(query="What is GitHub?"))

# Groq — same shape, different class
groq = ChatGroq(
    model="openai/gpt-oss-120b",
    temperature=0.7,
)
print(groq.invoke(query="Hello Groq!"))

# OpenRouter — hundreds of models behind one route
openrouter = ChatOpenRouter(
    model="deepseek/deepseek-v4.1-flash",
    temperature=0.7,
)
print(openrouter.invoke(query="Hello OpenRouter!"))
from rsroute.agents import (
    GeminiAgent, MistralAgent, GroqAgent, OpenRouterAgent,
)

# Your own tool — the client runs it for you
def web_search(query: str) -> str:
    ...

gemini_agent = GeminiAgent(
    tools=[web_search],
    max_tool_calls=12,  # default 10
)
print(gemini_agent.invoke(
    query="Latest news on GPT-6 Astra"
))

mistral_agent = MistralAgent(
    tools=[web_search],
    model="mistral-small-2603",
)
print(mistral_agent.invoke(
    query="What is the weather in Paris?"
))

openrouter_agent = OpenRouterAgent(
    tools=[web_search],
    model="deepseek/deepseek-v4.1-flash",
)
print(openrouter_agent.invoke(
    query="Search the latest open-weight model releases"
))
import requests

resp = requests.post(
    "http://localhost:8000/v1/gemini/chat",
    json={
        "query": "Explain vector databases",
        "master_key": "RSRoute_my_key",
        "temperature": 0.7,
        "max_tokens": 2048,
    },
    timeout=60,
)

data = resp.json()
if data["error"] != "No Error Found":
    raise RuntimeError(data["error"])

print(data["content"])

Prefer the raw REST API?

The rsroute client is optional. Every endpoint is plain HTTP, so you can call the gateway from any language — see the API reference above, or browse the client source at github.com/ItzRustam/rsroute-package.

FAQ

Questions worth asking.

Does RSRoute execute tools for me?

No. It advertises tools to the model and returns the model's tool_calls intent. Your application executes the tool and sends the result back. This keeps the gateway stateless and avoids running arbitrary code server-side.

How does authentication work?

A single shared master key, toggled by ENABLE_AUTH. The key must start with the literal prefix RSRoute_ and be at least 14 characters long. Clients send it as master_key in the JSON body.

This is gateway-level auth, not per-user or per-tenant. For multi-tenant exposure, put your own auth layer in front.

Why do errors come back as HTTP 200?

RSRoute reports failures in-band: the response body carries error and login: false. Always check the body rather than relying on the status code.

Is there a Python client?

Yes — rsroute-package is a thin client that wraps the gateway. It handles the master key, request shaping and agentic tool loops for you.

pip install rsroute, then from rsroute.chat_models import ChatGemini or from rsroute.agents import GeminiAgent. It reads the key from .env automatically.

Every provider has a matching pair of classes: ChatGemini / GeminiAgent, ChatMistral / MistralAgent, ChatGroq / GroqAgent, and ChatOpenRouter / OpenRouterAgent.

Can I use the server as a library instead?

Yes. The provider wrappers in app/providers/ are importable directly — ChatGemini(...), ChatMistralAI(...), ChatGroq(...), ChatOpenRouter(...). Both modes share the same abstraction layer, so behaviour is identical.

Is streaming supported?

Not yet. The chat classes explicitly document that streaming is unsupported in v1. Responses are returned in full.

What about OpenAI and HuggingFace?

Both are placeholder stubs in the current tree — license headers only, not wired to routes. Embedding endpoints are marked "coming soon" in the root index.

OpenRouter, by contrast, is fully wired: /v1/openrouter/chat, /v1/openrouter/agent and /v1/openrouter/parameters are live, and the Python client ships ChatOpenRouter and OpenRouterAgent.

Which models can I reach through OpenRouter?

Any model id OpenRouter serves. The gateway default is deepseek/deepseek-v4.1-flash, but you can pass openai/gpt-4o-mini, anthropic/claude-*, open-weight models, or anything else in OpenRouter's catalogue — no code change, just a different model value.

Use the providers object to control which upstream OpenRouter routes to, and app_title / app_url so your usage is attributed correctly.

How do I deploy it safely?

Terminate TLS and add CORS at a reverse proxy. Keep real keys in an ignored keys.env or in the deployment environment — never in a tracked .env. And set ENABLE_AUTH=true: it defaults to false, which would expose every provider key behind the gateway.
